# 첫 방문 이름 및 선택 기록 · 2026-11-10

## 요청과 구현

사용자가 처음 들어올 때 이름을 입력받고 선택한 결과를 기록으로 남기도록 요청했다.

- 첫 방문에 이름 또는 별명을 입력해야 추첨을 시작한다. 공백·제어 문자·20자 초과를 검증하며 이 기기에서 이름을 기억한다.
- 상단에서 이름 변경이 가능하다. 이름은 표시용이며 소유권을 이름 문자열로 구분하지 않는다. 같은 브라우저의 이름 변경은 계정 전환이 아니다.
- 추첨 시 `candidate` 상태로 로컬 임시 결과만 생성한다. 내 여행 기록이나 Firebase 저장 대기열에 자동으로 넣지 않는다.
- 결과의 **이 결과 기록하기**, 또는 최근 추첨 결과에서 체크 후 **선택한 결과 기록하기**로만 기록에 남긴다.
- 선택한 기록에는 추첨 당시 `travelerName`을 보존한다. 이름 변경으로 이전 기록을 바꾸지 않는다.
- 기존 이름 없는 기록을 보존한다. 임시 결과와 저장한 기록 모두 새로고침 뒤 유지한다. JSON 내보내기도 두 목록을 구분한다.
- Firebase에 연결하거나 재시도해도 미선택 임시 결과는 업로드하지 않는다. 선택 기록만 기존 익명 UID 경로로 저장한다.

## 변경 파일

- `src/profile.js`: 이름 검증 및 기기 내 기억.
- `src/app.js`: 첫 방문 모달, 이름 변경, 임시 결과 체크·단건/다중 기록, 이름 표시와 내보내기.
- `src/storage.js`: 후보/선택 기록 분리, 중복 선택·재시도 처리, 미선택 업로드 차단.
- `public/index.html`, `theme.css`: 입력 화면과 선택 목록, 모바일 헤더 및 기록 버튼.
- `firestore.rules`: `travelerName` 검증 추가. 기존 이름 없는 기록과 호환하며 UID 소유권 제한 유지.
- `tests/profile-records.test.mjs`, `tests/firestore.integration.mjs`: 선택 여부에 따른 저장, 이름 검증·보존 및 보안 검사.
- `firebase.test.json`, `package.json`: 전용 테스트 포트·규칙 연결을 재현하는 명령.
- README, Firebase 연결 안내, 결정 및 검증 문서 갱신.

브라우저 검증은 테스트용 별명과 개발용 로컬 기록으로 진행했다. 스크린샷은 로컬 `verification/name-selection/`에 보관하며 기록 화면을 GitHub 저장소에 업로드하지 않는다. 원래 사용자의 공개 사이트 추첨·기록 화면은 보존했다.

처음 에뮬레이터 실행은 기존 8086 포트 점유로 시작하지 못했다. 별도 설정을 옮기는 과정에서 규칙 파일 경로가 누락된 실행은 0/7 실패했으며 합격으로 계산하지 않았다. 원본 규칙과 동일 해시를 확인한 복사본으로 7/7 통과한 뒤, 프로젝트 루트의 `firebase.test.json`으로 실제 규칙을 직접 읽는 최종 명령도 7/7 통과했다. 이번 검증에서 남은 에뮬레이터만 식별해 정리했으며 기존 8086 포트의 프로세스를 종료하지 않았다.

## 미실행 및 다음 단계

Firebase 공개 웹 설정은 아직 null이다. 이름 포함 실제 클라우드 저장·기존 Firebase 프로젝트의 규칙 배포는 미실행이며, 이번 에뮬레이터 통과를 실제 클라우드 완료로 표시하지 않는다. 연결할 때 최신 `travelerName` 허용 규칙을 기존 앱 규칙과 안전하게 병합해야 한다.

웹 기능은 GitHub Pages로 배포해 테스트할 수 있다. 실제 Firebase 저장 검증은 프로젝트 설정 수령 후 가능하다.
